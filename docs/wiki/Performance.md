# 性能与内存 / Performance

本页保留 **2026-10-25 Windows Release 历史对照**，不是 2026-10-27 文档整理后源码的重新测量，也不代表当前所有场景的性能。数据来自当时保存的完整正式样本，不使用最好一次替代中位数。

## 环境与口径

Windows 11 Pro 10.0.26300、Ryzen 9 7945HX（16 核/32 逻辑处理器）、约 31.7 GiB 系统 RAM、Qt 6.12 / Rust 1.99 / MSVC 14.51 Release。完整默认窗口、一个真实本地 Shell、合成 ASCII/CJK 输出，物理客户区 **1488×992，DPI 119**。Rust/Qt 配置隔离，样本检查前台归属与固定几何，无并行 GUI 批次。

每版每场景预热一次，三对交替，第二对反转顺序。每次分别计算指标，再取三份中位数；分位数也取每次运行分位数的中位数，不能混池。以下两组 A/B 的基线不同，收益不可相加，也不是与 WindTerm 的对照。

- **CPU**：主进程 CPU 时间 / 实际墙钟，按一个逻辑核 100% 计，未除以 32，不含子 Shell。
- **Private**：进程私有提交；**Working Set**：驻留页，包含共享页；**私有工作集**：主进程独占驻留页，接近任务管理器“内存”列。三者不能互换，单位 MiB（2²⁰ 字节）。
- **Qt Paint / UpdateRequest**：绘制与窗口更新事件；不是 DWM 实际呈现 FPS、输入回显或远端 TUI 延迟，嵌套事件耗时不能相加。

## 内存预算与压缩的边界

每窗格默认 32 MiB 按需历史预算，设置范围 4–512 MiB；它既不在启动时预分配，也不是全进程或所有窗格的统一上限。Qt 窗口、字体、绘制缓存、协议和子进程另计。

更晚的 2026-10-26 压缩记录中，重复前缀长行的引擎 live heap 曾减少 11.81%，短行却增加 9.84%，唯一长行增加 6.51%，唯一长行投喂慢约 22–39%。这是特定引擎输入的比较，不是整窗资源指标；不能声称压缩对所有负载都更快更省。

窗口变大时 Qt 后备表面会增大。尚未证明“所有场景始终低于 30 MiB”，也未提供同环境当前版本与 WindTerm 的全面性能排名。

## 复现与证据边界

使用仓库中的 `native/scripts/measure-window-performance.ps1` 对两版同 profile 可执行文件采样，先核对脚本参数，保持窗口/DPI/字体/配置/负载一致；保存预热、全部正式样本、二进制哈希及失败尝试。丢前台、几何变化、无绘制或计时截断的样本不能接受。

本页所有保留的正式表格同时存于 [benchmark-samples.json](benchmark-samples.json)。原始逐事件日志、诊断目录和源码快照保留在维护者本机；这里的汇总不是独立复跑证明。后续版本应另行复测，不能将当前源码身份套到历史二进制。

上述样本不能替代最大化/4K、多窗格长时、真实 IME、外部 SSH/TUI、其他平台、发行包或远程 CI 验收。
